# Module 3 Checkpoint 02 — PostgreSQL database and loader

## Assignment requirements covered

This checkpoint implements Module 3 Part 1 and targets the full PostgreSQL/data-loading rubric section:

- `load_data.py` connects to PostgreSQL using `psycopg` 3.
- exactly one required table, `applicants`, is used.
- the table contains the 15 required columns with `p_id` as the primary key.
- the database input is `cleaned_applicant_data.json`, generated by the Checkpoint 01 cleaning pipeline.
- JSON `null` values become SQL `NULL`; missing GPA/GRE/comments/etc. do not crash the loader.
- repeated runs do not create duplicate applicants because `p_id` is the primary key and the loader uses an upsert.
- credentials are read from PostgreSQL environment variables and are never hard-coded or committed.
- an existing `applicants` table is checked before loading; the program fails clearly if its schema is not the required one.

## PostgreSQL setup

Install PostgreSQL locally and create a database for the assignment. A suitable database name is `gradcafe`. You can create it in pgAdmin, or from a PostgreSQL shell with:

```sql
CREATE DATABASE gradcafe;
```

From the PowerShell session that will run the assignment, set the standard PostgreSQL environment variables:

```powershell
$env:PGHOST = "localhost"
$env:PGPORT = "5432"
$env:PGDATABASE = "gradcafe"
$env:PGUSER = "postgres"
$env:PGPASSWORD = "YOUR_LOCAL_POSTGRES_PASSWORD"
```

These values apply to the current PowerShell process and are not written into the repository. Do not put a real password in README files, Python files, Git commits, or `.env` files committed to Git.

Install dependencies:

```powershell
python -m pip install -r requirements.txt
```

## Load and verify the data

Run the local audit first:

```powershell
python checkpoint_02_audit.py
```

Then load the data:

```powershell
python load_data.py
```

For a fresh database containing no applicants, the first run should end with approximately:

```text
Validated and processed: 30,011 cleaned records
Database rows before:   0
Database rows after:    30,011
Net new rows:           30,011
```

Run the exact command a second time:

```powershell
python load_data.py
```

The second run should keep the row count unchanged and report:

```text
Database rows before:   30,011
Database rows after:    30,011
Net new rows:           0
```

This is the checkpoint's practical idempotency test.

Finally, verify the live database row-for-row against the cleaned JSON input:

```powershell
python checkpoint_02_audit.py --database
```

Expected final lines include:

```text
CHECKPOINT 02 LIVE DATABASE AUDIT: PASS
Cleaned source rows matched exactly: 30,011
Primary key: p_id
Duplicate p_id rows: 0
```

## Design notes

`DOUBLE PRECISION` is used for the PostgreSQL float columns (`gpa`, `gre`, `gre_v`, `gre_aw`). The loader converts ISO date strings to Python `date` objects before passing them to psycopg. Existing rows with the same `p_id` are updated from the current cleaned source record instead of duplicated, which also allows corrected source data to be reloaded later without creating a second applicant row.
